# EU5 存档只读解码（把"机制到底生不生效"变成可查的数据）

> **一句话**：`.eu5` 存档 = 一行文本头 + 元数据块 + 一个内嵌 ZIP（`gamestate` 词元流 + `string_lookup` 名字表）；本档给出零写入的解码步骤、SAV03 词元表、日期公式，以及三个会把你带到坑里的 PowerShell/.NET 行为。
> **什么时候看**：要判断"某机制在本版本是否真的兑现"（而不是靠本体文案或记忆猜）、要确认"我的变量/修正有没有被写进存档"、或要在不启动游戏的前提下核对某个地点/国家的运行时数据时。
> **体量**：97 行 · 约 5 分钟通读

**版本基准**：EU5 **1.4.0**（安装分支 `ud009/release/next`，`clausewitz_release_tag: 2026.39.0`）。词元 id 表来自 **jomini master 分支 `crates/jomini/src/binary/lexer.rs`**（L0 开源解析层）；结构描述与社区 wiki `eu5.paradoxwikis.com/Save-game_editing` 一致，并已用真实存档逐字节验证。
**证据等级**：本档全部条目为 **A（文件/字节实查）＋ B（运行时存档观察）**。

## 一、先走最短路径：debug 模式存档是纯文本

| 头部位次 | 含义 |
|---|---|
| `SAV` | 固定 |
| 第 4–5 位 | 版本（`03` 为 1.4 常见） |
| 第 6–7 位 | **`00` = debug 模式纯文本存档**；`03` = packed 二进制 |
| 之后 8 位 | id/校验和；再 4 位 `0004`(文本) / `0006`(packed) |

⇒ **能复现的问题优先用 debug 起游戏存一份**：那是一份 `name = value` 文本（与 mod 文件同格式），grep 即可，不必解码。二进制解码只在"只有正式存档"或"要跨存档批量统计"时才用。

## 二、packed 存档的解剖（全程只读）

1. **备份**：`Copy-Item` 到工作区（例：`工具\_save_backup\<名>_<时间戳>.eu5`），比对字节数一致后再动。**永远不要往 `save games\` 写**。
2. **定位内嵌 ZIP**：整份文件里找 `50 4b 03 04`（`PK\x03\x04`）。实测一份 76,833,809 B 的 1.4.0 存档，ZIP 起始于偏移 **404,974**（前面是文本头 + 玩家纹章 + 一串未压缩的定义名）。
3. **截取并解压**：从该偏移到文件尾写成 `.zip`，用 `[System.IO.Compression.ZipFile]::OpenRead()` 解出两个条目：
   - `gamestate` —— 实测 331,457,190 B（压缩后 75 MB）
   - `string_lookup` —— 实测 3,167,904 B
4. **`string_lookup` = 5 字节头 + 连续 Hollerith 串**（`u16` 长度 + 该长度字节）。按出现顺序编号即为索引。
   - 头里的"条数"字段（实测 `0x0276` = 630）**只覆盖第一段**，别拿它当总数；一直解到 EOF（实测该档共 **66,166** 条）。
   - 导成 `索引<TAB>名字` 的文本再查。**键名与字符串值都在这张表里**——这是整条解码链的关键。
5. **`gamestate` 是词元流**，不是文本。明文里搜 `integration`、`core=`、`variables` 一律 0 命中，属正常。

## 三、SAV03 词元表（键 = `5b 0d <低字节> <高字节>`）

| 类别 | 词元 id（LE 两字节写在小端前两字节处） | 载荷 |
|---|---|---|
| 结构 | `0x0001` = `=`，`0x0003` = `{`，`0x0004` = `}` | 无 |
| 查表引用（**SAV03 主用**） | `0x0d5a` / `0x0d5b` / `0x0d5c` / `0x0d5d` | 1 / 2 / 3 / 4 字节的 `string_lookup` 索引 |
| 查表引用（老存档） | `0x0d3e`(16) `0x0d40`(8) `0x0d41`(24) `0x0d3f`(32)；`0x0d43..0x0d46` 为 1.0.10+ 紧凑变体 | 同上 |
| 定长数 | `0x0014` U32 · `0x000c` I32 · `0x000d` F32 · `0x0167` F64 · `0x029c` U64 · `0x0317` I64 · `0x000e` BOOL(1 B) | 见宽度 |
| **定点小数（1.4 的主力数字）** | `0x0d47` = 0；`0x0d48..0x0d4e` 正、宽 1–7 B；`0x0d4f..0x0d55` 负、宽 1–7 B | 值 = 原始整数 ÷ **100,000**（固定 5 位小数） |
| 字符串 | `0x000f` 引号串 · `0x0017` 裸串 · `0x0d5e` SAV03 串 · `0x0d42` 空串 | `u16` 长度 + 字节 |
| 颜色 | SAV03：查表串 `rgb` + 一个 `{ … }` 通道块；老档用 `0x0243` | — |
| 其它 | 未在上表的 2 字节值 = **游戏 token**（1.4 的 gamestate 只有 ~28 个，例：`0x09de` = `metadata`） | — |

**读法要点**
- 一个"键"就是 `5b 0d + 索引(16 位)`；键后常有 `01 00`（= 词元 `=`）再接值。
- **只能从"键的起点"向前 dump 才对齐**。从任意偏移切入必然错位。
- 记录里有变长子块（如 `ownership_history = { {…} {…} }`），所以别写"整档解析器"；用**"键 + `=` + 标量"的定点识别**（先在窗口内找目标键，再读它后面的值）。要全量结构化就用 jomini 的 `eu5save` crate（有 `melt`）或 PDX Unlimiter。
- 索引 → 键名：查第二步导出的那张表。例（1.4.0 某档）：`cores=42973`、`scripted_cores=42974`、`scripted_core_country=42975`、`scripted_core_grant_date=42976`、`cultural_unity=42980`、`integration_data=43046`、`core=43049`、`zzz_core_ready_years=43058`。

### ⚠️ 三种查表宽度在**同一份存档里并存**（实测，只搜一种必漏）

| 用途 | 词元 | 该档实测命中 |
|---|---|---|
| 索引 < 256 的**键名** | `0d5a` + u8 | `variables`=29,355、`name`=31,421、`value`=92,554（改用 `0d5b+u16` 搜 ⇒ **0 命中**） |
| 索引 ≥ 256 的**键名** | `0d5b` + u16 | `cores`=18,566、`scripted_core_grant_date`=9,927 |
| **值位上的字符串**（变量名 `flag = <名>`、枚举名等） | 老词元 `0d3e` + u16 | `zzz_core_ready_years`=20,068、`zzz_core_progress`=2,168、原版 `disease_outbreak`=157 |

⇒ **同一个索引，在"键位"和"值位"用的是不同词元**。查 mod 自定义**变量名**要搜 `3e 0d <lo> <hi>`；查**字段名**才搜 `5b 0d <lo> <hi>`（小索引换 `5a 0d <ix>`）。
⇒ 变量条目的实测形状：`flag = <0d3e+名> data = { type = <0d5a+'value'> }` 之后紧跟的 `0c 00 …`（I32）才是该变量的值；再往后的 `identity` 是**逐条递增的记录号**，量级几十上百、分布看着极像"数值统计"，**极易误当成值**。

## 四、日期

整数 = **自 -5000 年起的小时数**，`((年 + 5000) * 365 + 儒略日) * 24`，**不计闰年**（儒略日：1 月 1 日记 0）。

```powershell
function ToYear([int64]$hours) { $days = [math]::Floor($hours / 24); return [int]([math]::Floor($days / 365)) - 5000 }
```
实测锚点：1657.6.4 存的档，该字段 = `58315776` 附近；`55514280` → 1337 年（游戏用它当"历史核心/无记录"的**哨兵值**，不是真实年份）。

## 五、三个必踩的坑（都验证过）

1. ⚠️ **`.NET String.IndexOf` 默认按"当前区域性"比较**。把存档字节按 Latin1 转成 `String` 再搜 4 字节键时，needle 里 `U+00A8`、`U+00A7` 这类**零权重字符会被忽略**，于是给出**假命中**（实测：把 `5b 0d 32 a8` 报在 `5b 0d 03 01` 处）。
   ⇒ 必须用 `$text.IndexOf($n, $start, $count, [System.StringComparison]::Ordinal)`，**并且命中后再逐字节核验**；或者干脆手写字节循环。这条坑会把统计结果"看起来完全合理"地污染掉——最难发现的一类。
2. ⚠️ **拼小端整数用 `-shl`，不要用 `[Math]::Pow`**：`Pow` 返回 `double`，混进 `[int64]` 累加会炸（报 `[System.Object[]] 不包含名为 'op_Division'`，症状是"某些字段读到 0/空"而不是报错）。
3. ⚠️ **PowerShell 变量名大小写不敏感**：`param([string]$Out)` 与函数体里的 `$out = New-Object List` 是**同一个变量** ⇒ 参数被局部值顶掉，写文件路径变成空串。凡"参数名"和"局部名"不得只差大小写（本项目已有毁掉 11 个本地化文件的同类事故）。

另外两条纪律：**别对 Steam 目录做递归**（杀软会拦），以及**先证明你的扫描能发现命中**（拿一个已知应当存在的键当阳性对照，才允许采信它报的 0）。

## 六、这套方法能回答的问题（真实案例）

| 问题 | 解法 | 结论形态 |
|---|---|---|
| 效果给的核心会在 100 年后消失吗？ | 找 `scripted_core_grant_date`，按"授予年 × 该地点 `cultural_unity`"分三组对照 | 会——但只在到期时文化仍不对；详见 `vanilla\vanilla-territory-integration.md` |
| 我的 mod 在这个档里生效过吗？ | `string_lookup` 里有没有 `zzz_*` 变量/修正名（**注意：表里有名字 ≠ 该键被写过，要再数词元命中**） | 间接/直接证据各一档 |
| 某个效果到底写没写进对象？ | 数该键的字节级词元命中，并读它后面的标量 | 条数量级 + 取值分布 |

## 七、最小可复用件

本库不带二进制存档样本；实战脚本模板见案例 mod 工作区（`工具\_save_extract\`：`dump.ps1` 词元读取器、`verify_byteside.ps1` 字节级全量核对、`decisive.ps1` 分组对照、`sample_unity.ps1` 抽样）。要点已在 §三—§五，脚本只是把这三节写成 PowerShell。
