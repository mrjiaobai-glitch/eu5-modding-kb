# 编码损坏：两类机理、可逆判定与抢救方法（2026-10 实例）

来源：《刀锋与王座》2026-10 EU5 1.4 适配轮。三个脚本文件的中文注释损坏，
其中 **两个 100% 还原成功、一个确认不可还原**——正反对照完整，故机理可判定。
**本文件是 `pitfalls.md` 第五节（本地化 BOM）的展开**，专讲"注释已经乱了怎么办"。

---

## 0. 先结论：两类损坏，一种能救一种不能

| | A 类：UTF-8 被当 GBK 读 | B 类：经自定义字符集映射 |
|---|---|---|
| 典型字形 | `鍚堝悓`（合同）、`瑙勫垯`（规则） | `濞戞挸顦伴埀`、`闁汇埄鍨抽` |
| 码点范围 | 正常 CJK（U+4E00–U+9FFF 的 GBK 双字节区） | 含 **PUA（U+E000–U+F8FF）** |
| 可逆性 | **可逆（实测 124/124 行还原）** | **不可逆（信息已丢）** |
| 特征 | 无或极少 `?` | `?` 密度高（实测 2.9%） |
| 抢救 | GBK 回环（见第 2 节） | 只能按代码语义重写 |

**实测对照（同一 mod，同一天）**：

| 文件 | 损坏字形 | 还原结果 |
|---|---|---|
| `zzz_blades_and_thrones_monthly_pay.txt` | A 类 | **79/79 行完美还原** |
| `subject_types\mercenary_company.txt` | A 类 | **45/45 行完美还原** |
| `scripted_effects\blades_and_thrones_conversion_effects.txt` | B 类 | 全部路径失败 |

## 1. ⚠️ 第一铁律：无 BOM 的 UTF-8 文件绝不能用 PowerShell 5.1 读写

**这是 A 类损坏的成因，也是最容易重犯的坑。**

Windows PowerShell **5.1** 在中文系统上：
- `Get-Content` 对**无 BOM** 的 UTF-8 文件按 **ANSI 代码页（936/GBK）** 解码
- 解出的乱码再用 `Set-Content` 写回 → 乱码被**永久烙进文件**

```
原始 UTF-8 字节  ──按 GBK 解码──▶  鍚堝悓  ──按 UTF-8 存回──▶  鍚堝悓（烙死）
   合同
```

**为什么专挑"无 BOM"**：有 BOM 时 PS 5.1 会正确识别 UTF-8。而本 mod 的
`main_menu\setup\` 等目录**官方要求"必须 UTF-8 无 BOM"**，正好落进陷阱。

### 动手前先确认执行环境

```powershell
[System.Text.Encoding]::Default.WebName     # utf-8 = PS7 安全；gb2312/gbk = PS5.1 危险
$PSVersionTable.PSEdition                   # Core = PS7；Desktop = PS5.1
```

- **PS 7（Core）**：默认 UTF-8，无 BOM 也按 UTF-8 处理 → **安全**
- **PS 5.1（Desktop）**：危险，读写无 BOM 文件必须显式指定编码

### 安全读写模板（任何版本都适用）

```powershell
# 读：显式 UTF-8
$t = [System.IO.File]::ReadAllText($p, (New-Object System.Text.UTF8Encoding($false,$false)))
# 写：显式 UTF-8 + BOM（mod 惯例带 BOM）
[System.IO.File]::WriteAllText($p, $t, (New-Object System.Text.UTF8Encoding($true)))
```

**永远不要**用 `Set-Content` / `Out-File` 处理 mod 脚本文件（默认编码随版本/系统变）。

## 2. A 类抢救：GBK 回环（实测有效）

### 原理

把乱码字符**按 GBK 编回字节**，再**按 UTF-8 解码**，即得到原文：

```
鍚堝悓  ──GBK 编码──▶  E5 90 88 E5 90 8C  ──UTF-8 解码──▶  合同
```

### 代码

```powershell
$gbk = [System.Text.Encoding]::GetEncoding(936)
$u8  = New-Object System.Text.UTF8Encoding($false,$false)
$restored = $u8.GetString($gbk.GetBytes($mojibakeLine))
```

### 实测效果

```
前: #   鍚堝悓宸ヤ剑鍏碉紙浣庣骇锛夆攢鈹€瑙勬ā鈹€鈹€> 寮哄姏浣ｅ叺鍥斤紙楂樼骇锛?
后: #   合同工佣兵（低级）──规模──> 强力佣兵国（高级）──
```

常用字命中率接近 100%，**极少数行尾字符因当年转换时已丢失，表现为 `�?`**——这部分补不回来，占比很小（实测 215 字符 / 105 个 `?`）。

### ⚠️ 只对 A 类用，且必须"只改坏行"

**对 B 类文件、或对完好的行使用此方法会把好行弄坏**。实测教训：
对新文件里一行**完好**的中文注释做 GBK 回环，结果变成
`# ���������� scope ��Ƕ�� effect ...`——**抢救方法本身成了破坏源**。

**安全做法**：先按第 3 节判定类别，**逐行判定、只改判为 A 类的行**，改前整文件备份。

## 3. 可逆性判定流程（动手前必跑）

```
① 该行含 PUA 码点（U+E000–U+F8FF）？
     是 → B 类，不可逆，放弃还原（改为按语义重写）
     否 → 继续
② 该行含 `?`（U+003F）且密度高（>1%）？
     是 → 很可能已丢失信息，标存疑
     否 → 继续
③ 做 GBK 回环，检查还原结果的**常用汉字命中数**
     用常用字表（的一是在不了有和人这中大为上个国…）计数
     ≥3 → A 类，还原成功，可采用
     0–2 → 不是这条路径，不要写入
```

```powershell
# ① PUA 检测
([regex]::Matches($line,'[\uE000-\uF8FF]')).Count
# ② '?' 密度
([regex]::Matches($line,'\?')).Count / $line.Length
# ③ 常用字命中
([regex]::Matches($restored,'[的一是在不了有和人这中大为上个国我以要他时来用们]')).Count
```

### 方法论铁律：**先用一个已知可还原的样本自证方法有效**

本次的翻车点：我第一次判定"不可逆"时，只抽了一行做回环测试，
而那行**恰好**是 B 类/含丢失字符的行 → 我据此下了全局结论"不可逆"，
**差点放弃了 125 行本可完美还原的原文**，还多做了一轮有损的手工重建。

> **判定"不可逆"之前，必须：**
> 1. 取**多个**样本（≥5 行，含文件头与中部）
> 2. 先用一个**已知能还原**的样本验证方法本身有效
> 3. 看**统计量**（常用字命中率），不看单行观感

这与 `pitfalls.md` 第十一节那条"假阴性比假阳性危险得多"是同源病根。

## 4. B 类：确认不可逆时的证据

`conversion_effects.txt` 的坏行试过全部常见路径，**常用汉字命中均 ≈ 0**：

| 路径 | 常用字命中 |
|---|---|
| GBK(936) 回环 | 0 |
| UTF-8 二次解码 | 1–2（噪声） |
| Latin1(28591) | 0 |
| CP1252 | 0 |

**判定依据（两条同时成立才敢下结论）**：
1. 坏行含 **7 个 PUA 码点** → 用了非标准/自定义字符集映射，不是标准代码页回环
2. `?` 占 **2.9%** → 部分字符在转换时被替换，**信息已丢**，不是"字节还在、只是解读错"

**处置**：按代码语义重写注释，并在文件头标注"本注释为重建，非原文"。
重建时**必须核对注释描述的数值与 `script_values` 实际值一致**，
并参照同文件**未损坏行**的写法风格（本次用一行未坏的注释逐字对照，验证了重建风格一致）。

## 5. 排查清单：接到"注释乱码"报告时

1. **先做全库扫描**，摸清范围与类别（`tools\` 里的检测正则 + 第 3 节判据）
2. **找副本**：`mod_backup\`、创意工坊已发布版、旧日志。⚠️ **别高兴太早**——
   本次四份副本（本地+2 备份+工坊）乱码数**完全一致**（259/259/259/259），
   证明损坏发生在**第一次备份之前**，副本救不了；但**副本可用来对照完好行**
3. **按类别抢救**：A 类 GBK 回环；B 类语义重写
4. **改前备份、改后校验**：括号配对 + BOM + 效果定义数 + 行数
5. **抢救脚本须"只改坏行"**，且写入用显式 UTF-8 编码

## 6. 顺带修正的旧判断

`cases\laws-events-and-estates-2026-09.md` 第 5.4 节曾写：
> "没有 U+FFFD 也不代表可逆……只能重建不能还原"

**该结论已被本次推翻**（对 A 类而言）：A 类乱码同样不含 U+FFFD，
但 GBK 回环可 **100% 还原**。真正的判据是**PUA 码点 + `?` 密度**（见第 3 节），
不是 U+FFFD。该节已同步更正。
