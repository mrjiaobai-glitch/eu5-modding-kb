# 官简中缺口全量排查（2026-10，EU5 1.4-open-beta）

> **场景**：为一款改善官方简中的本地化 mod 做"还有哪里没译"的全量排查。反复得到的结论互相矛盾，最后定位到**基准选错 + 统计脚本静默丢数据**两个病根。
> **可复用的东西**：一套能真正找出缺口的判据流程，以及 4 个必须避开的假判据。

---

## 一、四个假判据（全都用过，全都误导过）

按使用顺序排列，越往后越隐蔽。

### 假判据 1：「值里没有汉字」= 未译 ❌

误报率极高。命中的绝大多数是**语言无关的引擎语法**：

```
CATEGORY_HOSTILE_ACTIONS        # 纯标识符，不该译
$MEN$@manpower!                 # 纯格式串，不该译
@tax_efficiency![SCOPE...]      # 图标 + 表达式，不该译
[character|e]                   # 概念引用
```

实测：1913 条"纯拉丁字母"里，**只有约 545 条是真需要翻译**的，其余是标识符/格式串。

### 假判据 2：「值里有拉丁字母」= 未译 ❌

漏掉**假阴性**更致命的一类：**官中值是空字符串 `""`**，一个字母都没有。

```
artist_events.18.a: ""          # 官英有文本，官中为空 → tooltip 显示空白
```

这类比"显示英文"更严重（界面直接空白），但任何"含拉丁字母"的判据都抓不到它。

### 假判据 3：「与英语逐字相同」= 未译 ❌（1.4 特有）

**1.4 把英语本地化也当成待翻译目标清理过**——大量键在英语侧被删除或置空，但**中文侧仍有英文残留值**。于是：

```
与官英逐字比对 → 官英没这个键 → 判为"非缺口"
但官中该键的值其实是英文散文，玩家看得见
```

实测：拿英语当基准时，`battle_for_the_strait`（海峡之战，274 条）**整条链被判为不存在**，因为它连同语言版本一起从英语里删了。而它在 `error.log` 里明确报过：

```
Failed to find 'battle_for_the_strait' from database for link 'situation'
```

**结论：1.4 不能用英语本地化当唯一基准。**

### 假判据 4：直接用 rival mod 的键集合差集 ❌

创意工坊有同类 mod 时，很容易写"它有我没有 = 我缺失"。但：
- 它的键可能有大量**冗余**（本次对手 8698 键里 763 条值与官中逐字相同，写了等于没写）
- 它可能覆盖**未发布 DLC** 的键（玩家现在触发不到）
- 它有 108 个文件内重复键

差集能当**线索**，不能当**结论**。

## 二、正确判据（三源交叉）

### 源 A：`error.log`（最高可信）

```
D:\Documents\Paradox Interactive\Europa Universalis V\logs\error*.log
```

搜这些串，它们直接点名引擎渲染失败的位置：

| 报错串 | 含义 |
|---|---|
| `localization_util.cpp` / `Failed parsing localized text` | 该键的值里有**失效的方法调用**（官中从旧版英语翻译，1.4 改了方法名） |
| `Unlocalized text` | 该键无本地化 |
| `Failed to find '<X>' from database` | 引擎在找某个名字 `<X>` 的数据库条目，但只有本地化没有实体 → 说明该键是活内容 |
| `Duplicate localization key` | 重复键（含 rival mod 造成的） |

**注意日志在 D 盘**（`D:\Documents\Paradox Interactive\...\logs\`），不是 `C:\Users\<user>\Documents\`——本机 EU5 的用户目录整体在 D 盘，`C:` 下只有个空的 `mod` 壳。找错地方会得出"没有日志"的错误结论。

### 源 B：游戏数据库 / 脚本引用

引擎按**名字**查数据库条目（situation、battle、building…）。若某本地化键对应的条目存在于 `in_game\` 或 `dlc\`，它就是活内容，值得译。

按前缀数量排序即可看出哪些事件链是"活的"：

```powershell
# 统计各事件链的脚本引用数
Get-ChildItem $game -Recurse -File -Include *.txt | Select-String -Pattern "battle_for_the_strait" | Measure-Object
# → 101 处 → 活内容
# → 0 处 → 未发布内容，暂不译
```

### 源 C：与「英语 + 其他语言」的键集合对照

- **仅官英有、官中没有** → 真缺口
- **两边都有但值相同** → 疑似未译（需按假判据 2/3 过滤）

实测数据（本机 1.4-open-beta）：

| 项 | 值 |
|---|---|
| 官英键数（严格正则） | 212,429 |
| 官简中键数 | 241,287 |
| 两边都有 | 211,382 |
| **仅官英有**（官中完全没有） | **1,047** |
| 值完全相同 | 13,401（过滤后 6,752） |

## 三、鉴定方法：三层过滤

对"C 源"产出的候选清单，依次过滤：

```
第 1 层：值是否为空字符串？        → 是则查官英是否有文本；有则是真缺口（界面空白）
第 2 层：剥掉 [标签] $占位符$ #标记# @图标! 后，还剩几个实词？
        实词数 >= 3，或 >= 2 且总长 >= 14  → 真文本
        否则                              → 标识符/格式串，跳过
第 3 层：抽样 5 条人工看            → 确认判据没跑偏
```

**第 3 层不能省。** 本次抽样才发现"需翻译清单"里有 2/3 是 `CATEGORY_*`、`$VAL$@gold!` 这类不该译的东西。

## 五、翻译时的硬约束（EU5 本地化）

- **UTF-8 BOM 必须**（编辑器/write 工具会剥掉，每次改完补回）
- 首行 `l_simp_chinese:`
- 一个前导空格缩进
- 保留 `$PLACEHOLDER$`、`[Scope.Method]`、`\n`、`#T…#!`、`@icon!`
- **`[Concept('id','回退文本')]` 里的回退文本要译**（这是给玩家看的兜底文案），但标签本身与 id 不能动
- **代词要按语法转换**：`[X.GetHerHis]` 在中文里应译为「他的」并保留标签，或按中文语序省掉；**不能说"中文里代词可省"就整段删标签**——先确认句子在中文里读得通

### 翻译后必做的两项自动比对

1. **`[...]` 标签集合比对**（与官英原文）
2. **`$...$` 占位符集合比对**

本次这两项抓出 7 处真实错误，包括：代词标签重复（`GetHerHis` 应为 `GetHerHim`）、残留英文单词（`coastline`、`decentralization`、`cosmopolitan`、`medieval`）、希腊借词未处理（`meltemi`）。

**"残留英文单词扫描"是自动化能抓到、人工阅读抓不到的一类**——自己写的译文，读起来是通的，只有脚本能把 `coastline` 那几个字母揪出来。

## 六、本次同源故障：统计脚本静默返回 0

排查过程中，同一批统计**连续 4 次返回 `0`**，每次都像"已全部覆盖"，实际是脚本丢数据。

详细清单见 `../pitfalls.md` 第十四节。此处只留最有价值的一条：

> **`$dict[$key]` 在大字典（数万键）下会静默返回 `$null`**，于是 `$a[$k] -eq $b[$k]` **恒为 True**，统计出"冗余 = 覆盖总数"这种荒谬结果。改用 `foreach ($kv in $dict.GetEnumerator())` 并只读 `$kv.Key` / `$kv.Value`。

**判据**：结果出现 `0`，或出现"两个不同的量恰好相等"，**一律先怀疑脚本**，不要当成结论。

## 七、可复用的排查顺序

```
1. 扫 error.log（源 A）→ 拿到引擎点名的键          ← 最高可信，先做
2. 扫脚本引用（源 B）→ 确认哪些键是活内容
3. 键集合对照（源 C）→ 拿到候选清单
4. 三层过滤 → 得到"真需翻译"清单
5. 逐文件取官英原文 → 翻译（保留标签/占位符）
6. 翻译后跑两项自动比对 + 残留英文扫描
7. 抽样人工核对
```

**第 1 步不可跳过。** 源 A 给出的键是引擎**已经报错**的，优先级最高，而且不受"英语基准不可靠"的影响。
